What is Linux?

Linux is a free, open-source operating system kernel created by Linus Torvalds in 1991. Combined with system tools and applications, it forms distributions such as Ubuntu, Debian, Fedora and Rocky Linux. It runs most web servers, cloud machines, Android phones and supercomputers.

1. Linux Architecture and Filesystem

The layers

Applications (browser, nginx, Python)
System utilities (ls, grep, systemctl)
Shell (bash, zsh)
Kernel (processes, memory, drivers, files)
Hardware (CPU, RAM, disk, network card)

User space is where applications, utilities and the shell run with limited privileges. Kernel space is where the kernel runs with full hardware access. Programs ask the kernel for help through system calls, so a crashing app can't take down the whole machine.

Filesystem hierarchy

Everything starts at / (root). There are no drive letters; extra disks are mounted into the tree.

/ ├── bin essential commands (ls, cp) ├── sbin admin commands (fdisk, reboot) ├── boot kernel and bootloader files ├── dev device files (/dev/sda) ├── etc configuration files ├── home personal folders (/home/alice) ├── root the root user's home ├── tmp temporary files, cleared on reboot ├── usr installed programs and libraries ├── var changing data: logs, mail, caches ├── proc live kernel and process info ├── opt optional third-party software ├── mnt manual temporary mounts └── media auto-mounted USB and DVDs

3. Managing Services on Linux

A service (daemon) is a program that runs in the background, such as a web server or SSH. systemd is the init system that starts the machine and supervises services. systemctl is the command you use to control it.

systemctl status ssh
sudo systemctl start ssh
sudo systemctl stop ssh
sudo systemctl restart ssh      # stop then start; briefly drops connections
sudo systemctl reload ssh       # re-read config without stopping
sudo systemctl enable ssh       # start automatically at boot
sudo systemctl disable ssh
sudo systemctl mask ssh         # block all starts, even manual
sudo systemctl unmask ssh
systemctl list-units --type=service
systemctl --failed
Start vs enable: start runs the service now; enable makes it run at every boot. Stop vs disable: stop ends it now; disable only removes boot startup. Use enable --now to do both. On some distros the SSH unit is called sshd.

Troubleshooting a service that won't start

Step-by-step 
systemctl status myapp            # read the last log lines and exit code
journalctl -u myapp -n 50         # last 50 log lines for this unit
journalctl -u myapp -f            # follow logs live
journalctl -xe                    # recent system errors with hints
sudo systemctl daemon-reload      # after editing a unit file

Typical causes: a typo in the config file, a port already in use, wrong file permissions, or a missing dependency.

4. Linux User and Group Management

The root user (UID 0) can do anything. Normal users have UIDs from 1000 up and use sudo for admin tasks. Every user has one primary group (GID) and any number of secondary groups.

FileContains
/etc/passwdUser name, UID, GID, home, shell (readable by all)
/etc/shadowHashed passwords (root only)
/etc/groupGroup names and members
/etc/sudoersWho may use sudo. Edit only with sudo visudo
whoami; id; groups                       # check who you are
sudo useradd -m -s /bin/bash alice       # create user with a home folder
sudo adduser bob                         # friendlier, interactive (Debian/Ubuntu)
sudo passwd alice                        # set a password
sudo groupadd devs                       # create a group
sudo usermod -aG devs alice              # add to group (-a keeps existing groups!)
sudo gpasswd -d alice devs               # remove from group
id alice                                 # user information
getent passwd alice
su - alice                               # switch user
sudo userdel -r alice                    # delete user and home
sudo groupdel devs
Always use -aG: usermod -G without -a replaces all secondary groups.

Ownership and permissions

Run ls -l and you see -rwxr-xr--: the first character is the type, then three triplets for user (owner), group and others. r=read (4), w=write (2), x=execute (1). Add the numbers per triplet.

ModeMeaningTypical use
755rwxr-xr-xPrograms, public folders
644rw-r--r--Normal files
700rwx------Private folders (~/.ssh)
600rw-------Private keys, secrets
chmod 755 script.sh
chmod u+x,g-w,o-rwx file.txt
sudo chown alice:devs report.txt     # change owner and group
sudo chown -R alice /srv/app         # recursive
sudo chgrp devs report.txt

5. Filesystem Usage

A disk is the hardware; a partition is a slice of it; a filesystem (ext4, XFS, Btrfs) organizes files inside the partition; a mount point is the folder where it appears. An inode stores a file's metadata, and each file uses one, so you can run out of inodes even with free space.

df -h              # space per filesystem, human readable
df -i              # inode usage
lsblk              # disks, partitions, mount points
blkid              # filesystem type and UUID
mount | grep sdb   # what is mounted
sudo mount /dev/sdb1 /mnt
sudo umount /mnt   # unmount (leave the folder first)
FilesystemNotes
ext4Default on many distros; stable, general purpose
XFSGreat for large files and servers; can grow but not shrink
BtrfsSnapshots, compression and checksums built in

"Disk is 90% full" - find the culprit

df -h                                        # 1. which filesystem is full?
sudo du -xh / --max-depth=1 2>/dev/null | sort -h | tail   # 2. biggest top-level dirs (-x stays on one filesystem)
sudo du -xh /var --max-depth=1 | sort -h | tail              # 3. drill into the biggest one
sudo find /var -xdev -type f -size +500M -exec ls -lh {} +   # 4. list big files
sudo journalctl --vacuum-size=200M           # 5. example safe cleanup: trim old logs
Tip: Deleted files still held open by a running process keep using space. Restart that service (sudo lsof +L1 finds them).
Inspect before deleting, and never remove files from /usr, /etc or /boot by hand.

6. IP Assignment and Service Ports

IPv4 / IPv6
32-bit (192.168.1.10) vs 128-bit (fe80::1) addresses.
CIDR
/24 = mask 255.255.255.0, 254 usable hosts.
Gateway
The router that leads off your network.
DNS
Turns names into IP addresses.
MAC
Hardware address of a network interface.
TCP vs UDP
TCP is reliable and ordered; UDP is fast and connectionless.

Inspect before you change

ip addr           # addresses per interface
ip link           # link state and MAC addresses
ip route          # routing table (look for "default via")
ip neigh          # ARP/neighbor table

Interface names vary: eth0, ens33, enp0s3. Pick the one marked UP that has your current IP, and ignore lo (loopback).

sudo ip addr add 192.168.1.100/24 dev enp0s3   # temporary; lost on reboot
sudo ip addr del 192.168.1.100/24 dev enp0s3
sudo ip link set enp0s3 up
sudo ip link set enp0s3 down
Bringing down the interface you're connected through (e.g. over SSH) will drop your session.

Connectivity troubleshooting

ping -c 4 8.8.8.8            # 1. internet reachable by IP?
ip route                     # 2. is there a default gateway?
ping -c 4 google.com         # 3. fails only here? DNS problem
nslookup google.com
dig google.com +short
curl -I https://example.com  # 4. can you reach a web service?
ss -tuln                     # 5. what is listening locally?

Which process is listening on port 8080?

ss -tuln                       # flags: t=TCP u=UDP l=listening n=numeric
